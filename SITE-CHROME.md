# Website header / footer / menu changes — where to edit (do this every time, no need to be told)

Bhim's standing instruction (2026-10-04): when asked to change the top menu, bottom menu/footer, branding or any
"site chrome" on the owner websites, apply it EVERYWHERE it lives, test, then commit + push. Don't wait to be told
which pages. Always keep the whole footer (links, copyright, tagline, AI notice) visible; keep corners square
(a rounded gap at the screen corner is the macOS browser window, not the page — don't chase it).

## 1. `os/bpupadhyaya.github.io` (equalinformation.com) — ~133 HTML pages
- **Shared CSS:** `style.css` is linked by 130 pages. Anything purely visual (sticky footer, nav look, brand pills)
  goes here ONCE and applies to all of them. Current footer: `footer { position: sticky; bottom: 0 }` so the whole
  footer is always on screen; the nav is `position: fixed`.
- **Duplicated markup (NOT shared):** every page carries its own copy of the nav `<ul class="nav-links">` (and the
  `<ul class="footer-links">` footer list). Adding/removing/renaming a menu item means editing ALL pages with a
  script. Pattern used for "Games": regex on `^\s*<li><a href="(index\.html)?#apps">Apps</a></li>` and append the new
  `<li>`; index.html uses `#games`, all other pages use `index.html#games`. Always run a count afterwards
  (`grep -c` per file) and make sure every page that has the old item has the new one.
- **Pages with their own full design (converted 2026-10-04 after Bhim found them missed):** `lifeos-privacy.html`, `lifeos-terms.html`,
  `resume.html`, `openwallet-safety.html` load `chrome.css` (GENERATED from style.css by `python3 build-chrome-css.py`: only header/footer/brand rules)
  instead of the whole style.css (which would clash with their own .hero etc.). `openwallet-features.html` uses style.css and had no footer (added).
  The ONLY page without UI is `google80639b387c252ede.html` (Google verification file). There are NO exceptions: all 136 UI pages carry the new header + sticky footer.
  After ANY chrome change in style.css run `python3 build-chrome-css.py` and re-check these pages.
- **MANDATORY EXHAUSTIVE AUDIT before reporting done (Bhim caught a miss once):** list EVERY *.html in the repo (`find . -name '*.html'`, all folders), then assert on each:
  new header (`ei-word`), `#games` link, `footer-links`, `<footer`, a chrome stylesheet (style.css or chrome.css), the toggle script. Report the exact list of files changed.
- Home page only: `index.html` has the Games section (`#games`), the app cards (`#apps`) and the Arcforge flagship.
- Cache: browsers cache ~10 min (GitHub Pages `max-age=600`); tell Bhim to hard-refresh (Cmd+Shift+R).

## LESSONS LEARNED (mistakes already made - do not repeat)
1. **Skipped pages instead of covering them (2026-10-04).** When asked to restyle header/footer on bpupadhyaya.github.io I changed the 130 pages that share `style.css` and silently skipped `lifeos-privacy`, `lifeos-terms`, `resume`, `openwallet-safety`, `openwallet-features` because they had "their own design". Bhim had explicitly said to look for pages with separate header/footer code and found the miss himself. FIX = no exceptions inside this repo; pages with their own CSS load the generated `chrome.css`.
2. **Searched by assumption, not exhaustively.** Do not rely on "pages that contain X". List EVERY `*.html` (`find . -name '*.html'`), assert the new chrome on each, and report the exact changed list. Also verify the pages reachable from every dropdown (Release Notes, Privacy Policy, Terms of Service, App Support, Support), not only the ones you remember.
3. **Duplicated markup is not shared.** The nav and footer lists are copied into each page; a menu item change needs a scripted edit over all pages, plus a count check afterwards.
4. **Scope confusion.** Separate sites under equalinformation.com (insurance-site, tools, global-intelligence-site, ...) keep their own branding; only bpupadhyaya.github.io gets this chrome. Do not ask again, do not restyle them.
5. **Same lesson for standalone apps:** Tiger and Goat 1.0.0 shipped opening straight into the game (no About / How to Play page) and needs a 1.0.1 republish. Flow is always icon -> About page -> game.
6. **Before saying "done":** run the audit, LOOK at screenshots (desktop + phone width), commit + push, and tell Bhim which files changed.
